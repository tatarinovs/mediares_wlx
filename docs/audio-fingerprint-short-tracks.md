# Проблема коллизий `Audio_Fingerprint` на коротких треках (< 30 с)

**Дата:** 2026-11-17  
**Источник:** [core/src/audio_fingerprint.rs](../core/src/audio_fingerprint.rs)

## Суть проблемы

На треках короче `WINDOW_SEC` (`30.0` с) разные по содержанию файлы с одинаковой длительностью в целых секундах часто получают **одинаковый `Audio_Fingerprint`** и попадают в ложные дубликаты в Total Commander.

### Воспроизведённый пример

```text
d:\MP3\Beatles\The Beatles 2\sound\1994 - Live At The BBC 2\11 - 1822!.mp3
  duration: 10s, PCM hash: 1ed855bb1489f381, Audio_Fingerprint: 10s_11_11_11

d:\MP3\Гражданская оборона\Издания на CDs 2004–2012 гг\[2005 · MZ 250-2] Тоталитаризм\13. В поле растёт молочай.mp3
  duration: 10s, PCM hash: 6a9aca29064a39e1, Audio_Fingerprint: 10s_11_11_11
```

## Причина в коде

1. В `fingerprint()` ([audio_fingerprint.rs](../core/src/audio_fingerprint.rs#L603-L613)):
   - `WINDOW_SEC = 30.0`, `WINDOW_AT = [0.25, 0.5, 0.75]`.
   - `let window = ((WINDOW_SEC * frames_per_sec) as usize).min(n);`
   - `let start = center.saturating_sub(window / 2).min(n - window);`
2. Когда длина слышимой части `n` меньше 30 секунд, `window == n`, поэтому `n - window == 0` и `start == 0` для **всех трёх** окон (`25%`, `50%`, `75%`).
3. Все три окна считают `window_bits()` по одному и тому же отрезку `0..n` и дают три одинаковых байта (`XX_XX_XX`, например `11_11_11`).
4. Вместо `3 × 6 = 18` бит спектрального хэша (262 144 комбинации) остаётся всего **6 бит (64 варианта)** + округлённая длина в секундах (`10s`). На коротких треках (скиты, интерлюдии, панк-треки) вероятность коллизии становится 1 к 64.

## Варианты решения (для обдумывания)

1. **Пропорциональное окно для коротких треков (`window = min(30 с, span / 3)` или `min(30 с, n / 2)`):**
   - Для трека длиной 10 с окна по ~3–5 с вокруг `25%`, `50%`, `75%` не будут полностью совпадать, возвращая все 18 бит различий между началом, серединой и концом трека.
   - Нужно проверить на перекодированных копиях коротких треков, не ухудшается ли устойчивость 6-битного `window_bits` при уменьшении окна с 30 с до 3–5 с.
2. **Уточнение длительности / отказ от фингерпринта для слишком коротких треков:**
   - Сейчас `MIN_AUDIBLE_SEC = 3.0`. Если поднять порог или не менять формат для длинных треков, а менять только правило выбора окна при `n < WINDOW_SEC`, длинные треки вообще не затронутся.
3. **Не забыть при изменении алгоритма:**
   - Повысить `VERSION` в [core/src/disk_cache.rs](../core/src/disk_cache.rs#L19), чтобы старые кэшированные `AudioFingerprint` не смешались с новыми.
